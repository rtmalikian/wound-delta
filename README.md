# WoundDelta

**Open-source wound-change measurement for home care, wound clinics, and telehealth follow-up. Photograph the wound, line it up with its ghost, and get a measured change: area change %, redness spread, darkening, and a trend. Change is measured in code, not guessed by a model. The app ships its own OpenAI-compatible AI gateway and runs self-hosted, so photos never have to leave the building.**

The question in wound follow-up is rarely "what is this wound?" It is "is it getting better, and should I worry before the next visit?" Today that gets answered with a ruler, or with memory. Published comparisons put ruler measurement error as high as 44%, while imaging-based measurement claims under 4% (vendor figure, Tissue Analytics). In the US, an updated 2025 compendium counts 10.5 million Medicare beneficiaries living with wounds, about 1 in 6, at $22.5B a year in Medicare cost. Most of those wounds are followed at home, by patients and caregivers with a phone.

WoundDelta is a subtraction. Show the patient their previous photo as a translucent ghost overlay so they re-photograph from the same angle and distance, then align and diff the two frames in code. The diff is the measurement. The diff is also the token saving: an unchanged wound costs zero model calls, and only the changed region ever reaches a model, at low detail.

**This software measures change. It does not diagnose, and it does not recommend treatment.** Every output is information for a clinician to review. See SECURITY.md for the plain limits, including the medical-device boundary.

## The measurable failure, and what moves it

| Metric | Current workflow | With WoundDelta |
|---|---|---|
| Area measurement error | Ruler on a curved, irregular wound: error reported up to 44% | Pixel diff after alignment. Eval harness on synthetic pairs with known ground truth: **area-change MAE 0.07 percentage points** (max error 0.12). Synthetic only; real-photo accuracy is unproven, see below |
| Cost per check | A visit, or a photo sent into a thread and eyeballed | Frugal tier: **median 260 estimated tokens per pair, 1 model call**, and **0 calls** when the photo is unchanged or the change is negligible. Full tier measured 590 tokens with a verifier pass |
| Deterioration spotting | Patient memory, next scheduled visit | Deterministic red-flag pattern checks on every pair: rapid expansion, redness spread, darkening, no measurable change over 14+ days. Fixture recall **10/10**, benign fixtures quiet **4/4** |
| Evidence for the trend | Notes like "looks better" | An area series per wound, with every comparison stored as measured numbers, not adjectives |

The eval harness in `tests/test_eval.py` fails the build if area-change MAE reaches 10 points, if red-flag recall drops below 0.90, or if the frugal median token estimate passes 300 per pair. Current results, run on the shipped synthetic fixtures: **MAE 0.07, recall 1.0, frugal median 260 tokens.**

Honest note on those numbers: the fixtures are generated by the same code family that measures them (`app/wounddelta/synth.py`), drawn ellipses on a skin-tone field. They prove the pipeline is internally correct: alignment, segmentation, diff, budgets, gates. They do not prove accuracy on real wounds, real skin tones, or real phone photos. That needs a labelled clinical photo set, and it is roadmap issue #1.

## How it works

```
 Previous photo ──► ghost overlay capture guide (line the wound up
                    with its ghost: same angle, distance, light)
 New photo ──────► hash check ── identical? ──► stop. Zero model calls.
                    │
                    ▼
              Align (FFT phase correlation) ──► segment both frames
              (redness + darkness channels) ──► pixel diff
                    │
                    ▼
        Measurements, in code: area change %, grew/healed pixels,
        redness spread %, darkening, red-flag pattern checks
                    │
                    ▼
        Gateway phrases the numbers (frugal: changed crop only,
        detail:low; full: full frame, detail:high + verifier pass)
                    │
                    ▼
        Patient-readable summary + clinician trend, numbers intact
```

Design rules that do the safety work:

1. **The model never measures.** Every number comes from deterministic code in `app/wounddelta/imaging.py`. The language model receives a JSON block of measurements and phrases it. In the full tier, a second pass checks that every number in the summary actually appears in the measurements block.
2. **Patterns, not diagnoses.** The red-flag checks (rapid expansion at +25% area, redness spread, darkening, stall over 14 days) are stated constants in one file. A flag says "raise this with your care team". It never names a condition and never suggests a treatment.
3. **The hash gate is real.** If the new photo is byte-identical after load, or the measured change is negligible and no flags fired, the pipeline returns a templated answer and the gateway ledger shows zero chat calls. The tests assert this, they do not just describe it.

## Two tiers, one gateway

Tier is a routing profile on the same gateway, chosen by the `model` name (`wound-delta-frugal` / `wound-delta-full`), an `X-Tier` header, or one env var. Same endpoints, same JSON schema, same UI, same eval harness. It is one product with the escalation dial turned up, not two products.

| | Frugal (default) | Full / commercial |
|---|---|---|
| Vision pass | Changed-region crop only, `detail:low` (85 tokens flat) | Full frame, `detail:high` (765 tokens at 1024px) |
| Calls per pair | 0-1 | 2 (summary + verifier) |
| Measured cost | Median 260 est. tokens | 590 est. tokens on the same fixture |
| Memory | Last pair | Full longitudinal history |
| What the spend buys | The measurement itself | A second-pass check that the summary's numbers match the measurements, finer edge detail for the model pass, trend context across all prior photos |

The tile maths (85 vs 765 tokens) is published OpenAI vision pricing arithmetic. The accuracy gain of the full tier is a hypothesis the harness measures per tier, not a claim.

## The architecture: the product ships its own AI gateway

WoundDelta serves OpenAI-compatible endpoints (`/v1/models`, `/v1/chat/completions`, `/v1/embeddings`) from inside the app, and every AI feature calls those endpoints. Nothing talks to a vendor API directly. One environment variable picks the backend:

- `stub` (default): deterministic, rule-based. No model, no keys. This is what CI and the demo run.
- `local`: an OpenAI-compatible server on your own hardware (Ollama, llama.cpp, vLLM) with a vision model such as LLaVA. Photos never leave the home or clinic. This is the deployment the product is built for.
- `upstream`: any OpenAI-compatible provider, for teams that accept that trade-off.

This gateway is the shared platform skeleton across this weekly product series. Week 1's [Discharge Decoded](https://github.com/rtmalikian/discharge-decoded) shipped the gateway and redaction gate for discharge plans, Week 2's [Prior-Auth Co-Pilot](https://github.com/rtmalikian/prior-auth-copilot) reused it for prior auth, and Week 3 keeps the skeleton and swaps in the imaging domain module. See docs/ARCHITECTURE.md.

## Quickstart

```bash
git clone https://github.com/rtmalikian/wound-delta
cd wound-delta
cp .env.example .env
docker compose up --build
# open http://localhost:8000
```

Or without Docker:

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --port 8000
```

Try the synthetic demo in the UI (the same fixtures CI measures), or:

```bash
curl -X POST "http://localhost:8000/api/demo/compare?kind=worse" \
  -H "X-Tier: frugal"
```

## API sketch

| Route | What it does |
|---|---|
| `GET /v1/models` | Lists `wound-delta-frugal`, `wound-delta-full`, and the stub model |
| `POST /v1/chat/completions` | OpenAI-shaped chat, multimodal content parts supported, tier by model alias or `X-Tier` header |
| `POST /v1/embeddings` | OpenAI-shaped embeddings (longitudinal summaries) |
| `POST /api/cases` | Create a wound case (label passes the PHI redaction gate) |
| `POST /api/cases/{id}/captures` | Upload a photo capture (PNG/JPEG, max 8 MB) |
| `POST /api/cases/{id}/compare` | Compare the two most recent captures: measurements, flags, summary, token ledger |
| `GET /api/cases/{id}/trend` | Area series and total change for the case |
| `POST /api/demo/compare?kind=healing\|stable\|worse` | Synthetic pair with known ground truth, compared live |
